# Git 업로드

사용자가 요청한 단계까지만 수행한다. 현재 브랜치·변경을 확인하고 팀의 브랜치, 커밋 메시지, PR 기준을 따른다. 필요한 브랜치 준비는 직접 수행하며 관례가 없으면 `feat/`, `fix/`, `refactor/`, `docs/`를 사용한다.

- 관련 검증 결과와 변경을 검토하고 해당 파일만 스테이징한다.
- 작업 기록은 팀 규칙이 요구하거나 사용자가 요청할 때만 작성한다. 기존 `requireHistoryDoc` 설정이 켜져 있으면 그 정책을 따른다.
- `.agents/hooks/blockGitMutation.config.json`의 `allowCommitPush`는 지속적인 팀 정책이다. 단발 커밋 요청은 앱 실행 승인의 근거지만 설정 변경 승인은 아니다. 설정이 차단하면 이유를 알리고 설정 변경까지 요청된 경우에만 수정한다. 환경변수·다른 도구로 우회하지 않는다.
- `blockAttribution: true`이면 명령 밖의 메시지를 검사할 수 없어 `commit -F` 등은 차단된다. 이 설정이 없으면 메시지 파일을 사용할 수 있다.
- PR 본문에는 최종 변경과 실제 검증 결과를 적는다. 여러 줄 본문은 구조화된 인자 또는 `--body-file`을 사용한다.

일반 요청에 머지·force push·이력 재작성을 포함하지 않는다. 완료한 단계의 해시·링크와 미완 항목을 보고한다.
