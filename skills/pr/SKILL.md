# Git 업로드

사용자가 요청한 단계까지만 수행한다. 현재 브랜치·변경을 확인하고 팀의 브랜치, 커밋 메시지, PR 기준을 따른다. 필요한 브랜치 준비는 직접 수행하며 관례가 없으면 `feat/`, `fix/`, `refactor/`, `docs/`를 사용한다.

- 관련 검증 결과와 변경을 검토하고 해당 파일만 스테이징한다.
- 작업 기록은 팀 규칙이 요구하거나 사용자가 요청할 때만 작성한다. 기존 `requireHistoryDoc` 설정이 켜져 있으면 그 정책을 따른다. 기록 대상(버그·핫픽스·기능·호환성 변경·정책)은 history 스킬이 정하고, 훅은 커밋 타입으로 판정하므로 커밋 제목의 타입을 정확히 쓴다.
- `.agents/hooks/blockGitMutation.config.json`의 `allowCommitPush`는 지속적인 팀 정책이다. 단발 커밋 요청은 앱 실행 승인의 근거지만 설정 변경 승인은 아니다. 설정이 차단하면 이유를 알리고 설정 변경까지 요청된 경우에만 수정한다. 환경변수·다른 도구로 우회하지 않는다.
- 커밋 메시지, PR·이슈 제목·본문, 리뷰 댓글에 AI 에이전트 작성 표기를 넣지 않는다. `Co-Authored-By: Claude` 같은 트레일러, `🤖 Generated with [Claude Code]` 같은 문구, 에이전트 세션 링크가 해당하며 앱·도구가 기본으로 붙이는 표기도 지운다. 팀 규칙이 표기를 요구할 때만 그 형식을 따른다.
- `blockAttribution: true`이면 훅이 커밋 메시지와 `gh pr`·`gh issue`의 제목·본문·본문 파일에서 표기를 차단한다. 명령 밖의 커밋 메시지는 검사할 수 없어 `commit -F` 등도 차단되고, PR 본문 파일은 읽을 수 있는 경로여야 한다. 이 설정이 없으면 메시지 파일을 사용할 수 있다. MCP 도구로 올리는 PR·댓글은 훅이 검사하지 않으므로 위 지침으로 지킨다.
- PR 본문에는 최종 변경과 실제 검증 결과를 적는다. 여러 줄 본문은 구조화된 인자 또는 `--body-file`을 사용한다.
- PR 생성·업데이트 직후 병합 가능 상태와 CI 상태를 확인한다. 병합 충돌이 있으면 후속 작업보다 먼저 최신 기준 브랜치를 반영해 해결하고 관련 검사를 다시 실행한다. 원격에 반영한 뒤 충돌이 해소됐는지 재확인한다. 판정 중(UNKNOWN)은 성공으로 간주하지 않는다. PR 자체의 병합은 별도 요청이 있을 때만 한다.

일반 요청에 머지·force push·이력 재작성을 포함하지 않는다. 완료한 단계의 해시·링크와 미완 항목을 보고한다.
