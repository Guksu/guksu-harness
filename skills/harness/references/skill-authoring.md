# 팀 스킬 작성

코드에서 알 수 없는 프로젝트 절차와 반복 가능한 도구 사용법만 담는다. 일반적인 계획·구현·테스트 순서를 다시 설명하지 않는다.

- description에는 적용 작업과 경계만 짧게 쓴다. 특정 후속 키워드를 나열하거나 모든 관련 작업에 호출을 강제하지 않는다.
- 본문에는 요청 범위와 완료 기준, 필요한 참조 위치를 둔다. 관련 없는 참조를 한꺼번에 읽지 않는다.
- 반복되는 결정적 처리는 scripts에 두고 실행 검증한다. 문서·템플릿은 필요한 경우에만 만든다.
- Claude Code는 `.claude/skills/`, Codex는 `.agents/skills/`를 사용한다. 두 앱의 내용이 중복될 경우 정본과 동기화 방식을 팀이 정한다.
- 구조 검사는 frontmatter와 참조를 확인할 뿐 호출 정확성이나 효과를 입증하지 않는다. 실제 요청·유사하지만 적용하면 안 되는 요청으로 평가한다.

일반 편집 때문에 기록·협업·다른 스킬을 연쇄 호출하지 않는다. 별도 기록은 팀 정책 또는 사용자 요청에 따른다.
