# 하네스 절대 규칙 — 정본

이 파일이 하네스 절대 규칙의 **단일 출처**다. 오케스트레이터·에이전트 정의는 규칙 전문을 복제하지 않고 이 파일을 포인터로 참조한다("작업 전 `docs/harness-rules.md`를 읽는다"). 복제본은 반드시 드리프트한다 — 규칙 수정은 이 파일 한 곳에서만 한다.

규칙 1(git)·6(시크릿)의 실제 강제 수단은 산문이 아니라 **훅·deny 권한**이다(blockGitMutation·blockSecretAccess·branchGuard). 이 문서는 에이전트가 이유를 이해하기 위한 요약이다.

1. **git 작업은 사용자 전담.** commit·push·merge·branch 삭제를 에이전트가 수행하지 않는다. 종료 시 "커밋은 직접 진행하세요"로 안내만 한다. 예외 2종(모두 사용자 승인 기반): ① 사용자 확인된 브랜치 전환은 `branch` 스킬이 `git switch(-c)`로만 수행. ② 사용자가 명시 요청한 커밋·PR 업로드는 `pr` 스킬이 git-flow(main·dev·feat) 절차로 수행(`allowCommitPush` 옵트인 필요). 이때도 커밋 메시지·PR 본문에 Claude 작성 표기(Co-Authored-By 등)는 절대 넣지 않는다 — 훅이 기계적으로 차단한다. merge·rebase·force push·브랜치 삭제·PR 머지는 예외 없이 사용자 전담.
2. **코드를 생성하면 TDD가 기본.** 인수조건 = 테스트 케이스(Red→Green→Refactor), 종료 기준에 테스트 전체 통과 포함. 외부 인프라(DB·외부 SDK)는 단위 대상이 아니라 모킹/스모크로 분리. 테스트는 사전 합의된 공개 경계(seam — 호출자가 쓰는 인터페이스)에 쓴다 — 어느 경계를 지킬지는 설계 문서에 기록된 합의를 따르고, 구현 내부에 결합된 테스트는 만들지 않는다.
3. **산출물은 파일 기반.** 약속된 경로(`docs/` 또는 `_workspace/`)에 쓰고 읽는다. 중간 산출물은 보존한다(감사 추적·부분 재실행). 작업 기록은 공통 워크로그 템플릿(`docs/templates/worklog.md` — 1.개요/2.작업내용/3.주의사항)을 따른다 — 형식이 통일되어야 에이전트 간·세션 간에 기록을 소비할 수 있다.
4. **단일 출처 문서를 따른다.** 프로젝트의 설계·컨벤션 문서가 있으면 그것이 정본이다. 어긋나면 임의 판단하지 말고 사용자에게 확인한다.
5. **QA는 경계면 교차검증 + incremental.** 존재 확인이 아니라 생산자(API/쿼리)↔소비자(훅/화면)를 동시에 읽고 shape을 비교한다. 전체 완성 후 1회가 아니라 모듈 완성 직후마다.
6. **시크릿은 읽지도 기록하지도 않는다.** `.env`·credential·키 파일을 읽지 않고, 산출물·로그·보고에 토큰/키/비밀번호를 옮겨 적지 않는다. 산출물은 보존되는 파일이므로(규칙 3) 기록된 시크릿은 곧 유출이다. 설정값이 필요하면 키 이름만 언급한다.
7. **컨텍스트는 절약형으로 설계한다.** 상시 로딩(CLAUDE.md·description)은 포인터 수준으로 최소화하고, 대량 읽기·리서치는 서브 에이전트로 격리해 요약만 회수하고, 대형 로그·데이터는 스크립트로 전처리한다. 메인 컨텍스트에 들어온 토큰은 이후 모든 턴이 다시 지불한다.
8. **출력은 읽는 사람이 이해할 수 있게 쓴다.** 질문·보고·문서 등 사용자에게 보이는 모든 출력에 적용한다. 전문용어는 써도 되지만 처음 나올 때 한 줄로 풀이하고, 한 문장에는 하나의 내용만 담고, 약어·영문 용어를 풀이 없이 나열하지 않는다. 어렵게 쓴 글은 사용자의 결정을 늦추고 답변의 질을 떨어뜨린다.
