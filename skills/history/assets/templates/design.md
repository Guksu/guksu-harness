# 설계: {시스템/하네스 이름}

| 항목 | 내용 |
|------|------|
| 최종 갱신 | {YYYY-MM-DD} |
| 상태 | {문답 진행 중 (N라운드) / 승인됨 ({YYYY-MM-DD})} |
| 참여 | {사용자 · 작성 에이전트} |

## 1. 목표와 완료 기준

{이 시스템이 무엇을 해결하는가 — 2~3문장. "다 됐다"를 판정하는 기준은 측정 가능한 문장으로 쓴다 (예: "테스트 전체 통과 + 배포 전 점검 blocker 0건").}

## 2. 범위

**포함:**

- {이번에 만드는 것}

**제외:**

- {이번에 만들지 않기로 합의한 것 — 제외를 명시해야 나중에 범위가 슬그머니 늘지 않는다}

## 3. 시스템 구조

{도메인·핵심 데이터와 흐름·기술 스택·주요 제약. 설계·컨벤션 문서가 프로젝트에 이미 있으면 경로를 적고 요약만 남긴다 — 그 문서가 해당 영역의 단일 출처다. 문답에서 확정된 도메인 용어는 "용어: 한 줄 정의" 목록으로 여기에 남긴다.}

## 4. 실행 방식과 역할

{실행 모드(직접 실행~에이전트 팀)와 선택 근거, 티어(라이트/풀). 풀 티어면 역할 분리와 각 역할의 책임 범위.}

## 5. 안전장치와 권한

{문답으로 합의된 것 — 보호 브랜치 목록, 커밋·PR 권한 옵트인 여부, 이 도메인의 고위험 도구(배포·결제·운영 DB 등)와 차단 방식, 검증자 게이트 사용 여부.}

## 6. 문답 기록

{라운드별 결정 요약 — 감사 추적. 번복된 결정은 지우지 않고 번복 사실을 새 행으로 기록한다.}

| 라운드 | 주제 | 결정 |
|--------|------|------|
| 1 | {주제} | {결정 요약} |

## 7. 미해결 질문

{합의하지 못했거나 나중으로 미룬 것. 없으면 "없음"으로 명시한다. 미해결을 남긴 채 진행하기로 했다면 그 합의 자체도 기록한다. 문답에서 묻지 않았지만 설계가 전제하는 가정도 여기에 적는다 — "가정: {내용} — {YYYY-MM-DD} 이 가정 위에 진행하기로 합의"처럼, 합의를 받은 것만 남긴다(합의받지 못한 가정은 질문으로 전환한다).}
