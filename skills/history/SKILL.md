# 선택적 작업 기록

작업 기록은 나중에 사람과 에이전트가 "왜 이렇게 됐나"를 찾을 때 읽는다. 모든 작업을 남기면 찾는 비용이 커진다. 그래서 기록 대상을 좁히고, 색인 한 파일로 찾게 한다.

## 언제 쓰는가

팀 규칙 또는 `requireHistoryDoc`이 요구하거나 사용자가 요청할 때 쓴다. 팀 규칙이 기록을 요구해도 아래 기록 대상이 아니면 쓰지 않는다. 사용자가 요청하면 대상과 관계없이 쓴다.

| 유형 | 커밋 타입 | 예 |
|---|---|---|
| 버그 | `fix` | 잘못된 동작 수정 |
| 핫픽스 | `hotfix` | 배포본의 긴급 수정 |
| 기능 | `feat` | 부 버전이 오르는 기능 추가 |
| 호환성 변경 | `타입!` 또는 `BREAKING CHANGE:` 꼬리말 | 주 버전이 오르는 변경 |
| 정책 | `policy` | 팀 규칙·훅 설정·권한·배포 조건 변경 |

`docs`·`refactor`·`test`·`chore`·`style`·`perf` 커밋만 있는 작업은 기록하지 않는다. 그 내용은 커밋 메시지와 PR 본문에 남긴다. 버전 목록은 CHANGELOG가 맡는다. 기록은 CHANGELOG에 없는 이유·검증·주의사항을 남긴다.

`requireHistoryDoc`이 켜진 저장소에서는 git 훅이 같은 기준으로 판정한다. base 이후 커밋(병합 제외)에 위 타입이 있는데 기록 문서가 없으면 push를 막는다. Conventional Commits 형식이 아닌 커밋도 기록 대상으로 본다. 팀은 `historyCommitTypes`로 대상 타입을 바꾼다(`["*"]`는 모든 push).

## 쓰는 법

1. `docs/history/{YYYY-MM-DD}-{slug}.md`에 작성한다. 같은 작업 문서가 있으면 갱신한다.
2. 프로젝트 `docs/templates/history.md`를 우선한다. 없으면 이 스킬의 `assets/templates/history.md`를 복사한다. 프로젝트가 고친 양식의 구조를 존중한다.
3. 머리 표의 "유형"에 위 표의 유형을 적는다. 여러 개면 모두 적는다.
4. 변경 이유, 결과, 실제 검증, 미실행·실패, 후속 사항을 남긴다. 채팅을 읽지 않은 사람도 판단할 수 있어야 한다.
5. 색인 `docs/history/README.md`에 한 줄을 추가한다. 없으면 이 스킬의 `assets/templates/history-index.md`를 복사해 만든다. 최신 기록을 표 맨 위에 둔다.

과거 기록을 임의로 삭제하지 않는다. 중복된 PR 본문이나 로그를 전문 복사하지 않는다.

## 찾는 법

기록을 찾을 때는 `docs/history/` 전체를 grep하지 않는다. 색인 `docs/history/README.md`를 먼저 읽고, 날짜·유형·제목으로 고른 문서만 연다. 색인에 없으면 그때 grep한다.

## 다른 양식

양식 제공은 기록 작성을 강제하지 않는다. 다른 선택 문서의 원본도 `assets/templates/`에 있다: handoff·retro·loop-spec·predeploy·design. 해당 작업에서 프로젝트 양식이 없을 때 필요한 파일만 복사하며, 양식 때문에 이 스킬을 추가 호출할 필요는 없다.
