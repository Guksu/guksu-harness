# History — 작업 기록

**PR 하나 = 문서 하나.** 완료된 작업의 보존 기록은 `docs/history/`의 이 문서 하나뿐이다 — 역할별로 각자 기록을 남기면 같은 작업이 여러 문서에 흩어져, 나중에 읽는 사람이 어느 것이 전체인지 알 수 없다.

## 작업 산출물과 기록을 구분한다

둘은 수명이 다르므로 다른 곳에 둔다.

| | 위치 | 수명 | 용도 |
|---|------|------|------|
| **작업 산출물** | `_workspace/` (gitignore) | 이번 작업 동안 | 역할 간 인계 — 계획서·구현 노트·QA 리포트처럼 다음 역할이 읽어야 흐름이 도는 것 |
| **기록** | `docs/history/` (커밋) | 영구 | 완료된 작업 1건의 정본. 산출물을 근거로 마지막에 종합한다 |

작업 중에는 `_workspace/`에 자유롭게 쓴다. 보존되는 것은 그 종합본 하나다.

## 기록 절차

1. **단위 확정** — 하나의 PR이 한 문서다. PR을 만들지 않는 작업이면 사용자가 한 번에 커밋할 범위가 단위다. 잘게 쪼개지 않는다.
2. **경로** — `docs/history/{YYYY-MM-DD}-{slug}.md`. slug는 브랜치 이름(`feat/{slug}`)과 맞춘다 — 브랜치↔기록이 이름으로 대응되어야 어느 기록이 어느 작업인지 추적된다.
3. **기존 문서 확인** — 같은 PR의 문서가 이미 있으면 **새로 만들지 않고 갱신한다.** `docs/history/`에 같은 slug가 있는지 먼저 확인한다.
4. **템플릿** — 프로젝트 `docs/templates/history.md`가 단일 출처. 없으면 이 스킬의 `assets/templates/history.md`를 프로젝트 `docs/templates/`로 **복사한 뒤** 사용한다. 베껴 쓰지 않고 복사한다 — 복사가 결정적이어야 프로젝트마다 미묘하게 다른 사본이 생기지 않는다.
5. **채우기** — `{중괄호}`를 채우고 안내 주석을 삭제한다.
   - 섹션 구조(1. 개요 / 2. 작업 내용 / 3. 검증 결과 / 4. 확인 필요·후속 / 5. 주의사항)는 추가·삭제·개명하지 않는다.
   - **"3. 검증 결과"는 실제 실행 결과만 적는다.** 실패는 실패로 적는다 — 통과만 적힌 기록은 다음 사람이 믿을 수 없고, 그러면 기록 전체가 무게를 잃는다.
   - 없는 섹션은 비워두지 말고 "없음"으로 명시한다 — 빈 섹션은 "안 쓴 것"과 "없는 것"을 구분할 수 없다.
   - 시크릿을 옮겨 적지 않는다. 보존되는 파일이므로 기록된 시크릿은 곧 유출이다.
6. **갱신 시 지우지 않는다** — "2. 작업 내용"에 항목을 추가하고, 방향이 바뀌었으면 바뀐 사실 자체를 기록한다(감사 추적).

## 누가 언제 쓰는가

- **쓰는 시점은 커밋·PR 직전이다.** 작업이 끝나야 검증 결과와 최종 변경 목록이 확정된다. `pr` 스킬은 커밋 전에 이 문서를 확인하고, 없으면 먼저 기록한다.
- **쓰는 주체는 작업 흐름을 끝까지 본 쪽**이다 — 여러 역할이 참여했으면 마지막 종합을 맡은 쪽(오케스트레이터 또는 마지막 역할)이 `_workspace/` 산출물을 근거로 하나로 합친다. 역할별 병렬 기록은 만들지 않는다.
- **기계적 강제** — `blockGitMutation` 훅의 `requireHistoryDoc`이 켜져 있으면 `docs/history/` 변경 없는 push가 차단된다. 훅이 그물, 이 스킬이 절차다.

## 다른 템플릿

이 스킬은 프로젝트 기록 템플릿의 **단일 출처**를 함께 관리한다. 각 문서의 작성 절차는 담당 스킬에 있다.

| 템플릿 | 용도 | 기록 위치 | 담당 스킬 |
|--------|------|----------|----------|
| `history.md` | 작업 기록 (이 스킬) | `docs/history/` | — |
| `design.md` | 시스템 설계서 | `docs/design/` | `harness` (설계 문답) |
| `handoff.md` | 세션 인계 | `docs/handoff/` | `handoff` |
| `retro.md` | 하네스 회고 | `docs/retro/` | `retro` |
| `loop-spec.md` | 루프 명세 | `docs/loops/` | `loop` |
| `predeploy.md` | 배포 전 점검 | `docs/predeploy/` | `fe-predeploy` |

프로젝트에 `docs/templates/{템플릿명}`이 있으면 그것이 단일 출처다. 없으면 이 스킬의 `assets/templates/`에서 복사한다.

## 하네스 연동

guksu-harness가 구축한 하네스에서는 Phase 2에서 템플릿이 티어에 맞게 프로젝트 `docs/templates/`로 복사되고, 도메인 스킬·에이전트 정의에 "작업 산출물은 `_workspace/`, 완료 시 `docs/history/` 기록"이 명시된다. 독립적으로도 언제든 호출 가능하다.
