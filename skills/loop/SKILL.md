# 반복 작업 설정

일반 개발에서 수정 → 테스트 → 재수정은 요청한 작업의 일부다. "테스트가 통과할 때까지 고쳐줘"만으로 루프 명세·별도 승인·에이전트 팀을 만들지 않는다.

## 별도 설정이 필요한 경우

- 세션을 넘어 정기 실행하거나 상태를 감시한다.
- 대량 항목을 반복 처리하며 실행 한도와 진행 상태를 저장해야 한다.
- 사용자가 별도 루프 또는 종료 검사를 요청한다.

먼저 현재 환경의 실행 수단을 확인한다. 특정 플랫폼의 `/loop`·예약 도구·Workflow가 있다고 가정하지 않는다. 도구가 없으면 지원되는 범위와 남는 제약을 알린다.

## 설정과 실행

1. 요청에서 목표·검증 명령·최대 반복·간격·기간을 추출한다. 이미 답한 값이나 승인한 작업을 다시 묻지 않는다.
2. 빠진 값 중 비용·외부 영향·완료 기준을 바꾸는 것만 질문한다. 로컬의 가역적 반복이면 최대 10회, 같은 실패 3회라는 기본값을 알리고 진행할 수 있다. 예약·감시의 간격과 종료 시점은 요청에서 확정한다.
3. 오래 유지할 반복만 `docs/loops/{slug}.md`에 목표, 실행 단위, 검증, 종료·중단 조건을 기록한다. 단발 수정에는 명세를 만들지 않는다.
4. 반복마다 실행 결과를 확인한다. 테스트 통과만으로 사용자 요구사항 전체가 충족됐다고 간주하지 않는다. 범위 밖 수정은 하지 않는다.
5. 성공 또는 한도·막힘에 도달하면 진행 상황·남은 실패·중단 사유를 보고한다. 실제 세션 인계가 필요할 때만 `handoff`를 작성한다.

## 종료 검사 훅 (선택)

`harness` 스킬의 `assets/hooks/verifierGate.mjs`를 설치하고 Stop 이벤트에 등록한다. 설치·업데이트는 `harnessManager.mjs`의 `--verifier` 미리보기를 사용할 수 있다. 설정은 훅 옆 `verifierGate.config.json`에 둔다:

```json
{
  "checks": [{ "name": "test", "command": "npm test" }],
  "maxIterations": 10,
  "stuckAfter": 3
}
```

- 실패 후 이어진 종료 요청도 다시 검사한다. 통과하면 종료한다.
- 최대 차단 횟수 또는 같은 실패 상한에 도달하면 한 번 보고를 요청하고 다음 종료를 허용한다.
- `maxTokens`는 선택이다. 제공되는 transcript의 입력·출력·캐시 생성 토큰을 더한 **세션 누적 근사치**로, 과금액·작업별 예산·실시간 강제 상한이 아니다. 설정했는데 transcript를 읽을 수 없으면 사유를 보고하고 중단한다.
- 검사 시점은 Stop 이벤트다. 실행 중인 명령을 예산 도달 즉시 취소하지는 않는다. 검증 명령은 건당 5분 제한이며 빠른 검사를 선택한다.
- 설정이 없으면 비활성이다. 설정 오류는 성공으로 처리하지 않고 오류 보고 후 종료한다.

등록과 권한의 상세는 `harness` 스킬의 `hooks-and-permissions.md` 참조 문서를 따른다. 별도 에이전트 생성은 반복 실행의 필수 조건이 아니다.
