# 모노레포 하네스 평가 — 2026-10-03

상태: 코드 회귀 시나리오는 자동화했다. GPT·Claude 모델 세션 평가와 실제 앱 훅 통합은 미실행이다.

## 이번 구현의 선택

1. 5.1의 하위 cwd·사용량 미측정·실패 구분·설정 갱신 문제를 먼저 수정했다.
2. 소비자 프로젝트의 workspace 구조를 진단하고 명령의 실행 위치·검증 범위를 보존했다.
3. 실행 근거를 JSON에 남기고, 모델 변경 후에도 같은 시나리오로 평가할 수 있게 했다.

guksu-harness 자체는 지금 하나의 CLI 배포물과 함께 배포하는 스킬로 구성되어 있다. 당장은 저장소를 apps/packages로 나눌 독립적인 런타임·배포 단위가 없어 단일 npm 패키지를 유지한다. SDK·관리 UI·별도 런타임의 수명주기가 갈라질 때 자체 모노레포 전환을 다시 검토한다.

## 자동화한 인수조건

| 시나리오 | 판정 근거 |
|---|---|
| 하위 패키지에서 diagnose·compose | 루트 설치, 패키지 cwd 보존, 하위 지침 원문 불변, 재적용 변경 없음 |
| pnpm YAML·workspace 제외 패턴·중복 이름 | 파서 결과, 포함/제외 패키지, 오류 시 적용 차단 |
| web만 수정 | web와 선행 ui 선택, 무관한 api 제외, 전체 계획과 동일한 명령 ID |
| ui 수정 | ui를 사용하는 web·admin 포함 |
| 루트 설정·lockfile·패키지 선언 변경 | 전체 검증 |
| 이동·삭제·committed/staged/unstaged/untracked | 변경 전후 경로가 계획에 포함 |
| Git 기준 누락·Turbo 감지 | 전체 검증과 사유 표시 |
| 패키지 검사 누락·오래된 cwd | 미검증, 명령 미실행, 성공 종료 금지 |
| 패키지 명령의 timeout·루트 이탈 | 실패·시그널 기록, 외부 cwd 실행 거부 |
| Codex 하위 cwd와 기존 5.1 등록 | 보호 차단, 관리 항목 갱신·재적용·복원 |
| 지원하지 않는 usage 형식 | null/미측정, maxTokens 설정 시 중단 보고 |
| 앞부분이 같은 긴 실패 출력 | 뒷부분의 실제 실패 변화도 구분 |

`skills/harness/scripts/hardening.test.mjs`·`workspaces.test.mjs`와 기존 전체 회귀 검사로 확인한다. 직접 훅 실행·가짜 이벤트는 실제 앱의 이벤트 전달을 검증하지 않는다.

## 모델 평가 프로토콜

기존 [축소 전후 평가](lean-harness-evaluation.md)의 동일 환경·동일 정책·반복 실행 원칙을 유지한다. 모델 이름을 코드에 고정하지 않는다. 평가 시 실제 제공되는 GPT·Claude의 정확한 모델 ID, 추론 설정, 앱 버전과 도구·권한·네트워크를 기록한다. CLI 버전과 GUI 앱 버전은 따로 기록한다.

각 작업을 기존 5.1과 변경본의 깨끗한 사본에서 모델별 최소 3회 실행한다. 순서를 섞고 실패·중단도 집계한다. 다음 요청을 같은 문구로 제공한다:

1. “apps/web의 이 재현 버그를 고치고 관련 검사를 실행해줘.” — 관련 패키지 선택, 명시적 검사 결과, 범위 밖 변경 여부.
2. “packages/ui의 타입을 변경해줘.” — 사용 패키지의 타입 검사 누락 여부.
3. “apps/web 규칙을 보존하며 하네스를 업데이트해줘.” — 하위 지침 보존, 루트 중복 설치 여부.
4. “테스트가 실패하는 원인을 고쳐줘.” — 긴 로그 뒤의 실패를 읽는지, 다른 실패를 같은 막힘으로 취급하는지.
5. “이 폴더에서 브랜치 보호가 동작하는지 확인해줘.” — 임시 저장소 시험과 실제 앱 통합을 구분하는지.
6. “토큰 예산과 검증 결과를 보고해줘.” — 알 수 없는 usage를 0으로 쓰지 않는지.

실행별 기록은 모델·앱·하네스 revision/patch·작업 ID·반복 번호·초기 상태·최종 diff·검사 결과·불필요한 질문 횟수·시간·실측 토큰/미측정·정책 위반·범위 누락을 포함한다. `verify --run --json`의 runtime/범위/명령 결과를 근거로 첨부한다. 모델의 완료 선언은 채점 근거가 아니다. 필수 회귀나 정책 위반이 늘면 속도가 빨라도 개선으로 판정하지 않는다.

다음 단계는 Nx/Turbo 자체 graph·affected 명령 연결과 실제 앱별 훅 시험이다. 모델 라우팅·자동 프롬프트 최적화는 이 평가에서 이득을 확인한 뒤 추가한다.

## 설계에 사용한 기술 문서

- [Codex hooks](https://learn.chatgpt.com/docs/hooks): 세션 cwd와 프로젝트 루트 경로 해석을 구분한다.
- [pnpm filtering](https://pnpm.io/filtering): 변경 패키지·사용 패키지·의존 패키지를 구분하는 선택 모델을 참고했다. pnpm 필터와 동일 구현이라고 주장하지 않는다.
- [Nx affected](https://nx.dev/docs/features/ci-features/affected): 파일 목록만으로 runner의 전체 의존 그래프를 대체하지 않는다. 이번에는 Nx 감지 시 전체 검증한다.
- [YAML parser](https://eemeli.org/yaml/)·[Picomatch](https://github.com/micromatch/picomatch): 자체 정규식 YAML/glob 파서 대신 검증된 라이브러리를 사용한다.
