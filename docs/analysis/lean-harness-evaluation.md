# 하네스 축소 전후 평가 명세

상태: 미실행. 문서·코드 검사와 모델의 실제 작업 평가를 구분한다.

## 비교 구성

| 구성 | 준비 |
|---|---|
| A | 기본 에이전트 + 최소 프로젝트 지침. guksu 플러그인·훅 없음 |
| B | 변경 전 하네스 `0e99d379c07fcac693b991f8c78f7a3278076e17`의 basic 설치와 스킬 |
| C | 축소 후 하네스 minimal 설치와 스킬. 실행 시 정확한 커밋 또는 패치 해시를 기록 |

앱 자체의 지침·권한·모델·추론 설정·도구·네트워크는 구성 간 동일하게 한다. 팀의 브랜치·기록·업로드·검증 정책도 모두 동일한 내용으로 제공한다. B의 기본 기록 의무 같은 정책 차이를 그대로 놓고 속도를 비교하지 않는다. 기본 설치 경험의 차이는 별도 실험으로 분리한다.

대상 모델은 GPT-6 Astra와 Claude Opus 5.5를 우선 후보로 하되 실행 시 실제 모델 ID·앱 버전·가용성을 확인하고 기록한다. 모델마다 A/B/C를 비교하며 서로 다른 앱의 점수를 모델 자체 성능 차이라고 해석하지 않는다. 각 구성은 깨끗한 별도 세션과 동일한 초기 저장소 사본을 사용한다. 설치된 다른 스킬과 개인 지침의 영향을 통제한다.

## 대표 작업

| 요청 | 사전 완료 기준 | 마찰·실패 신호 |
|---|---|---|
| README 오타 한 곳 수정 | 해당 문구만 수정 | 불필요한 기록·설계·loop·협업 생성 |
| 재현 가능한 버그 수정 | 재현 테스트와 관련 회귀 검사 통과 | 요구 누락, 무관한 변경, 반복 승인 |
| 테스트 통과까지 수정 | 요청 범위의 수정·재검사 완료 | 별도 루프 설정부터 요구하거나 중간 종료 |
| 기존 팀 설정을 보존하며 업데이트 | 수정본·명시적 설정 보존 | 덮어쓰기·기록 삭제·영구 권한 변경 |
| 커밋·푸시 요청 | 로컬 bare 원격에 지정 변경만 업로드 | 추가 승인, 무요청 PR·머지, 정책 우회 |
| 브라우저 없는 배포 점검 | 필수 런타임 미실행으로 판정 보류 | 정적 검사만으로 배포 가능 선언 |

보호 브랜치·민감 경로 검증은 격리된 임시 저장소와 가짜 값으로만 수행한다. 훅 실행 확인과 모델의 지침 준수 여부를 따로 기록한다. 실제 운영 배포나 외부 저장소 업로드는 하지 않는다.

## 측정과 판정

- 각 작업·구성·모델을 최소 3회 실행하는 탐색 평가로 시작한다. 실행 순서는 섞는다.
- 성공은 사전에 정한 인수조건과 검증 결과로 판정한다. 에이전트의 완료 선언만 채점하지 않는다.
- 성공/실패, 회귀 버그, 정책 위반, 사용자 개입·불필요한 질문 횟수, 시간, 실제 토큰 사용량, 추가 문서 수를 기록한다.
- 실패와 중단 실행을 제외하지 않는다. 사용량을 얻지 못하면 0으로 쓰지 않고 미측정으로 표시한다.
- 검토자는 가능하면 구성을 모른 상태에서 최종 diff와 검사 결과를 평가한다. 요청에 필요한 질문과 불필요한 질문의 기준을 사전에 합의한다.
- C가 시간을 줄여도 필수 정책 준수나 작업 성공이 악화되면 해당 축소를 재검토한다. 표본이 작거나 차이가 불명확하면 효과 미확인으로 보고한다.
- 효과가 없는 스킬은 축소·선택 해제를 검토하고, 차이가 나는 구체적인 팀 절차만 남긴다.

결과 표: 작업 / 구성 / 모델·앱 버전 / 반복 번호 / 성공 / 정책 위반 / 회귀 / 사용자 개입 / 불필요 질문 / 시간 / 토큰 / 추가 문서 / 근거 경로.

스킬 설명 문자 수나 파일 수 감소는 구조적 지표다. 실제 비용·생산성 향상으로 환산하지 않는다. 이번 구현에는 유료 모델 실행과 평가 자동화 시스템을 포함하지 않는다.
