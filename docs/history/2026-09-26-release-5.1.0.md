# 5.1.0 릴리스 준비

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-09-26 |
| 브랜치 | release/5.1.0 |
| PR | 미생성 |
| 기준 | origin/main의 a202213 (PR #27 병합) |
| 관련 경로 | package.json, .claude-plugin/, .codex-plugin/, CHANGELOG.md |

## 1. 개요

버전을 5.1.0으로 올리고 CHANGELOG의 Unreleased를 5.1.0 항목으로 바꿨다. 코드 변경은 없다. npm 배포는 하지 않았다(이 환경에 npm 로그인이 없다). 머지 후 `npm publish`로 배포한다.

배경: PR #27로 팀 맞춤 구성 명령 `diagnose`·`compose`·`verify`가 main에 들어갔다. npm에는 5.0.0만 있어 `npx guksu-harness diagnose`가 아직 동작하지 않는다. 기존 명령의 동작은 바뀌지 않았으므로 부 버전을 올렸다.

## 2. 작업 내용

- 버전: `package.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `.codex-plugin/plugin.json`을 5.0.0 → 5.1.0.
- `CHANGELOG.md`: `[Unreleased]`를 `[5.1.0] - 2026-09-26`으로 바꾸고, 업데이트 주의(없음 — `update` 동작 동일, 기존 설치에서 `compose` 실행 시 설치를 잇고 프로필을 낮추지 않음)와 npm 배포 미포함을 적었다.
- 이 기록.

## 3. 검증 결과

| 검증 | 명령·범위 | 결과 |
|------|------|------|
| 구조 검사(버전 일치 포함) | `npm run check` | error 0, warn 0 |
| 전체 회귀 | `npm test` | 170개 통과 |
| 배포 내용 | `npm pack --dry-run` | 이름 guksu-harness, 버전 5.1.0, 파일 64개, 테스트 파일 제외 |
| diff 공백 검사 | `git diff --check` | 통과 |
| npm 배포 | `npm publish` | 미실행 — `npm whoami` 실패(로그인 없음) |

## 4. 확인 필요 · 후속

- 머지 후 main에서 `npm publish`를 실행한다. `prepublishOnly`가 `npm run check`와 `npm test`를 먼저 실행한다.
- 배포 뒤 저장소 밖 빈 디렉터리에서 `npx --yes guksu-harness@5 diagnose --help`가 사용법을 출력하는지 확인한다.
- 원하면 `v5.1.0` 태그와 GitHub 릴리스를 만든다. 이 저장소에는 아직 태그가 없다.
- 실제 Claude Code·Codex 앱 안의 훅 실행과 모델 평가는 5.1.0에서도 미실행이다. `docs/history/2026-09-26-team-compose-mvp.md` 4절을 따른다.

## 5. 주의사항

- `--ci` 워크플로 양식은 `guksu-harness@5`를 쓰므로 5.1.0 배포 뒤 자동으로 새 버전을 받는다. 새 명령은 CI 검사(`check`)의 동작을 바꾸지 않는다.
- 플러그인으로 설치한 사용자는 앱의 플러그인 갱신을 해야 새 스킬 문구(팀 맞춤 구성 절)를 받는다. 이 저장소가 갱신을 강제하지는 않는다.
