## 1. 개요

하네스의 과도한 확인 절차와 문서·동작 불일치를 수정하고, 설치 상태 확인과 기존 파일을 보존하는 업데이트 도구를 추가했다. 전체 테스트 101개와 구조 검사가 통과했다. 실제 Claude Code 앱 안의 실행 및 별도 모델 세션의 요청 평가는 수행하지 않았다.

초기 로컬 분석은 v1.16.0에서 진행했으나 구현 전에 원격 최신 v2.2.0을 확인했다. report·digest 제거와 작업 기록 통합은 이미 반영돼 있어 다시 구현하지 않았다.

## 2. 작업 내용

- `skills/harness/SKILL.md`, `branch`, `loop`, `pr`: 점검은 읽기 전용으로 분리했다. 이미 받은 구현 승인을 유지하고 일반 테스트 재시도에는 별도 루프 명세를 요구하지 않는다. 브랜치 전략과 작성자 표기는 프로젝트 정책을 따른다.
- `skills/harness/assets/harness-rules.md`: 공통 규칙을 정본에 모으고 작은 수정의 불필요한 테스트·기록·역할 분리를 줄였다.
- `skills/harness/assets/hooks/verifierGate.mjs`: 연속 Stop 이벤트에서도 검사를 수행한다. 반복·막힘 상한 또는 설정 오류 시 중단 보고 후 종료하며 상태를 세션별로 저장한다.
- `skills/harness/assets/hooks/blockGitMutation.mjs`: 작성자 표기 차단을 `blockAttribution` 선택 정책으로 전환했다. 커밋·푸시 허용과 위험 명령 차단은 유지했다.
- `skills/harness/scripts/harnessManager.mjs`: 상태 진단, 변경 미리보기, 파일별 선택 적용, 설치 해시 추적, 기존 설정 병합, 제거, 백업 복원을 제공한다. 변경된 파일·등록은 충돌로 보존하고 오래된 계획은 거부한다.
- `skills/fe-predeploy/scripts/decideRelease.mjs`: 필수 검사를 못 했으면 배포 판정을 보류한다. 검사 목록 자체의 완전성은 계획한 범위와 별도로 대조하도록 명시했다.
- `README.md`, 참조 문서: 설치·첫 요청·문제 해결을 앞에 두고 상세 사용법을 분리했다. 이전 규칙과 충돌하는 설명을 갱신했다.
- `validateHarness.mjs`: 설치 추적이 기본 구성이면 협업 전용 템플릿을 요구하지 않는다.
- 플러그인 매니페스트와 변경 이력을 v2.3.0으로 갱신했다.

## 4. 확인 필요 · 후속

- 기존 프로젝트가 작성자 표기를 계속 차단하려면 훅 업데이트 전에 `blockAttribution: true`를 추가한다. 관리 도구는 권한 설정을 자동 변경하지 않는다.
- 실제 Claude Code 환경에 도입할 때 담당자가 `testing-guide.md`의 사용자 요청 시나리오와 Stop 이벤트 흐름을 확인한다.

## 5. 주의사항

- 관리자는 번들 공통 파일만 추적한다. 도메인 스킬·에이전트·CLAUDE.md는 별도 구성 대상이다.
- 상태 진단은 공유 설정 기준이며 현재 앱에서의 훅 실행을 보증하지 않는다. 훅은 모든 셸 우회를 차단하는 보안 경계가 아니다.
- 변경된 파일과 알 수 없는 기존 파일은 자동 덮어쓰지 않는다. 충돌 없는 파일만 선택해 별도 계획을 만들 수 있다.
- 백업은 설정 사본을 포함하므로 커밋하지 않는다. 동일 프로젝트에서 관리 명령을 동시에 실행하지 않는다. 적용 후 바뀐 파일이 있으면 자동 복원을 거부한다.
- `maxTokens`는 선택적 transcript 누적 근사치이며 실시간 강제 예산이나 과금액이 아니다. 검사 명령은 Stop 시점에 실행한다.
