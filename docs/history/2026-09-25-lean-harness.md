## 1. 개요

새 설치를 기록 양식 없는 minimal 구성으로 바꾸고, 기존 설치의 설정·문서·프로필을 보존했다. 일반 작업 지침을 줄여 팀 설정 관리와 실행 가능한 검증에 집중했다. 코드 검사는 통과했으며 실제 앱에서의 훅 실행과 모델 생산성 비교는 미실행이다.

## 2. 작업 내용

- `harnessManager.mjs`, CLI: 새 설치 minimal 기본값, update의 프로필 선택, 기존 basic·collaboration·프로필 없는 설치 호환. 최소 구성에서도 이미 추적한 양식은 계속 병합·업데이트하며 선택 제거 시 문서는 보존하고 추적·원본만 해제한다.
- 새 minimal 설치에서만 `requireHistoryDoc: false`를 명시한다. 기존·수동 훅과 설정은 덮어쓰지 않는다. 기존 설정에서 기록 요구가 생략된 경우 true였던 동작을 유지한다. 커밋·푸시 허용 기본 false는 유지한다.
- 설정 가져오기: minimal에 처음 가져온 양식도 추적과 병합 기준 사본을 등록한다. import 백업 복원은 문서·사본·추적 정보를 함께 되돌린다.
- Git 훅: worktree 일반 생성·조회 허용, 강제 생성·삭제·이동·정리 차단 유지. `commit -F` 등 간접 메시지는 작성자 검사 선택 시에만 차단하며 이력 재작성·강제 push 차단은 유지한다.
- 스킬 9개의 호출 이름은 보존하고 설명을 축소했다. branch·pr에서 일반 작업마다 다른 스킬을 연쇄 호출하지 않는다. history·handoff·프론트엔드·협업 절차는 선택 기능이다. fe-predeploy는 수정 요청까지 포함됐으면 수정·재검사를 이어간다.
- 코어 정책·협업·스킬 작성·출력·컨텍스트 문서를 축소했다. 구조 검사에서 특정 후속 키워드를 강제하거나 규칙 개수로 버전을 추측하던 로직을 제거했다.
- README·설치·보장 범위·플러그인 설명을 맞추고 CHANGELOG의 Unreleased에 기록했다. 버전은 main의 4.2.1로 유지했다.
- PR 준비에서 README에 미출시 기능의 로컬 실행법, CLI와 플러그인의 역할, minimal 전환 명령과 기록 정책 변경 방법을 추가했다.
- `docs/analysis/lean-harness-evaluation.md`: 기본 에이전트 / 변경 전 / 축소 후의 공정한 비교 조건과 측정 항목을 작성했다. 유료 모델 실행이나 평가 시스템 구축은 포함하지 않았다.

최초 회귀 실패는 최소 기본값으로 바뀐 설치 파일 수, 최신 규칙을 복사하던 구버전 테스트 fixture, 새 import 추적 상태의 기대값에서 발생했다. fixture를 실제 구버전 형태로 고정하고 새 최소 설치·전환·설정 보존·import 병합·복원 테스트로 검증했다.

기본 Python과 번들 Python에 PyYAML이 없어 스킬 형식 검사 실행이 실패했다. `/tmp/guksu-skill-validation` 가상환경에 PyYAML을 설치한 후 공식 검사기를 실행했다. 프로젝트 런타임 의존성에는 추가하지 않았다.

## 4. 확인 필요 · 후속

- 앱별 실제 훅 실행을 가짜 민감정보와 임시 저장소에서 확인한다. 등록 형식 검사는 실제 이벤트 실행을 대신하지 않는다.
- 평가 명세에 따라 모델별 A/B/C 비교를 수행한 뒤 추가 축소 여부를 결정한다.
- 배포 시 릴리스 버전과 기존 사용자 안내를 확정한다. 최초 구현에서는 업로드하지 않았으며, 후속 요청으로 구현 커밋 `adf9d2f`를 푸시하고 main 대상 PR #25를 생성했다. 배포와 설치된 플러그인 캐시 갱신은 포함하지 않는다.

## 5. 주의사항

- 기존 포인터·팀 규칙은 자동 변경하지 않는다. 그 안에 기록 의무가 남아 있으면 `update --profile minimal`만으로 해제되지 않는다. 팀이 포인터·규칙·requireHistoryDoc을 함께 검토해야 한다.
- `--ci`는 하네스 구조 검사다. 제품 테스트·배포 검사와 별개다.
- 훅은 등록된 경로의 명령 패턴을 검사한다. Bash 파일 쓰기, 기록의 내용 품질, 배포 체크리스트에서 아예 누락된 항목까지 보장하지 않는다.
- 단발 업로드 요청을 영구 허용 설정으로 바꾸지 않는다. 기존 차단 정책과 앱 권한은 별개로 유지된다.
